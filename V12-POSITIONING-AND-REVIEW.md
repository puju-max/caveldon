## Editorial rule
General pages explain cloud engineering *capabilities* and outcomes. AWS and Azure remain named platforms. Detailed technical reference studies and specialist tutorials **should** use exact service/product names where accuracy requires them.

## Updated customer-facing areas
- Services: cloud setup; **cloud migration & modernization** (including application, database, cloud-to-cloud, and hybrid); DevOps and CI/CD; security/governance; reliability; FinOps; and developing AI infrastructure. These remain grouped under three broader practices rather than seven main-menu items.
- Homepage: first challenge and Cloud & Platform Engineering card now mention cloud migration.
- Hero architecture diagram: uses neutral cloud environment/access-protection labels instead of an AWS account/WAF.
- Security pages: address **regulated or sensitive workloads** at healthcare and financial organizations *and* vendors serving them. Not all organizations are subject to all frameworks. CAVELDON supports technical implementation, not independent audits or certification.
- SOC 2: technical overview is provider-neutral. Existing AWS-specific **Engineering Lab** design and AWS technical articles retain explicit names as appropriate.
- Contact: migration option is accepted by both the form and backend validation.

## Microsoft Dynamics 365 scope caveat
Dynamics 365 is a business application suite, not a generic cloud hosting service. A Dynamics 365 migration can involve ERP/CRM configuration, licensing, data model mapping, business workflows, integrations and specialist platform knowledge. This is **not** automatically covered by cloud infrastructure or database migration skills. Only advertise Dynamics 365 implementation/migration when verified capability and delivery scope support it.

## Meaning of industry positioning
"Cloud engineering for healthcare / financial services" means cloud hosting, reliability, security and governance needs within healthcare or financial institutions, and possibly the platforms vendors supply to them. **It does not mean CAVELDON develops clinical software, runs a bank, issues HIPAA certifications or performs regulated independent audits.** Scope and professional obligations are determined per organization and workload.
