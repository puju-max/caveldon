# CAVELDON Engineering Work — publication standard

## What this section is

Three original **reference design studies**, each linked from `/work/`, with reusable Astro layouts and illustrations. Reference designs are concept-level engineering examples. They are **not** represented as deployed systems, verified security reviews or customer case studies.

## How a reference study becomes a demonstration

1. Choose a bounded, reproducible workload and publish a testable acceptance plan.
2. Create an isolated cloud account/subscription or lab with a budget and teardown controls.
3. Implement the minimum useful configuration with reviewed Infrastructure as Code.
4. Run and record functional, security, recovery, performance and cost checks appropriate to the study.
5. Publish sanitized source, configuration assumptions, test methods, limitations and measured results.
6. Promote the label from **REFERENCE DESIGN** to **VALIDATED DEMONSTRATION** only after there is objective evidence and review.

## How a demonstration becomes a client case study

- Obtain explicit permission to share any customer/employer-related information.
- Verify the release scope, figures, statements and use of names/logos.
- Separate original lab results from production-client results.
- Never imply professional certification, compliance attestation or independent audit authority that CAVELDON does not possess.

## Engineering quality rubric

Each study should answer five questions, in order: (1) what does the business need, (2) what is the system boundary, (3) why this approach over alternatives, (4) how would we detect failure or security weakness, and (5) which artifacts substantiate the claims? The page copy should be legible to a technical leader and a nontechnical buyer.
